# OrbitalDC Studio — an interactive physics simulator for orbital data centers

**▶ Try it live: [pratik-ingle.github.io/Space-data-centers](https://pratik-ingle.github.io/Space-data-centers/)**
— runs entirely in your browser (needs WebGL); nothing to install.

Browser-based engineering design-space exploration of a GPU compute cluster on
a satellite bus. Move a slider — the design re-sizes, re-masses and re-flies a
5-year mission live, and everything rolls up to one figure of merit:
**delivered PFLOP-years per tonne launched**.

```
workload → chip power (dyn + T-dependent leakage) → heat → coolant loop →
radiator (εσT⁴ out, env fluxes in) → junction temp → DVFS throttle →
effective FLOPS
   overlays: TID → leakage + mortality · SEU → checkpoint tax · SPE storms ·
   coating darkening · array fade · thermal-cycling fatigue · battery fade
```

Physical correctness beats visual polish: every visible effect comes out of
the integrated equations (documented per subsystem in [MODEL.md](MODEL.md);
every knob's default/range/meaning in the auto-generated
[PARAMS.md](PARAMS.md)), and the TypeScript core is validated against the
`sdcsim/` Python reference below to golden fixtures. Baseline: 32× H100-class
at 550 km dawn-dusk SSO → **147.0 PFLOP-yr, 3,219 kg, 45.7 PFLOP-yr/tonne**.

## Run it

The live site is the `gh-pages` branch, published from `app/` with
`npm run deploy` (build + push of `dist/`). To run locally:

```bash
cd app
npm install
npm run dev        # → http://localhost:5173
```

```bash
npm test           # 9 acceptance tests + Python-parity fixtures + UI suites
npm run build      # strict tsc + production bundle
node scripts/smoke.mjs   # drives the built app in Chrome end-to-end
npm run baseline   # CLI mission run → baseline_mission.json
npm run docs:params      # regenerate PARAMS.md from the schema
```

## What's in the app

- **Physics core in pure TypeScript** (`app/src/core/`, zero DOM imports) in a
  Web Worker: multi-rate integration — a 30 s fast loop through the orbit
  (two-node thermal network with unconditionally-stable exponential updates,
  leakage↔Tj fixed point, proportional DVFS, battery dispatch with bisection
  power cap) under ~2-week degradation epochs (TID, coating drift, array/battery
  fade, attrition, Daly checkpoint tax, Poisson storms).
- **3D scene**: Earth with a terminator driven by the same sun vector as the
  physics, orbit trace with its shadow arc, and a spacecraft whose radiator and
  wing **areas are the actual sized values** — radiator faces colored by live
  temperature, eclipse dims the vehicle when the fast loop says so.
- **Telemetry**: live strip + orbit-scale and mission-scale chart stacks
  (eclipse/storm shading, synced cursors, playhead), 1×–1,000,000× time warp,
  deterministic timeline scrubbing.
- **Design analytics**: live mass-budget bar, loss waterfall
  (throttle/attrition/checkpoint), sized-subsystem readouts, design warnings
  (never silently clamped), clickable event log, **A/B compare** with a pinned
  baseline overlaid on the charts, scenario presets, JSON export/import.
- **Monte Carlo**: seeded, bit-reproducible ensembles with a delivered-compute
  histogram (p5/p50/p95) and a Spearman tornado of which uncertainty moves the
  outcome.

Presets tell the design stories: the 550 km dawn-dusk baseline, an ISS-like
orbit with a full battery, the same orbit **battery-lean** (idles every
eclipse, cold-soaks, and Coffin–Manson fatigue eats the fleet — watch the
event log), and a solar-storm stress test.

# sdcsim — the Python reference underneath

Pure-Python (numpy + matplotlib) implementation of the same models; the
TypeScript core is a validated port of it (fixtures generated by
`scripts/gen_fixtures.py`).

## Architecture (multi-rate)

| layer | timescale | method |
|---|---|---|
| orbit transient loop (`orbitloop.py`) | 30 s steps, ~95 min orbit | 2-node thermal network (coolant, radiator) with exponential unconditionally-stable updates; quasi-static junction (fixed-point in leakage); proportional DVFS controller; battery dispatch with bisection power cap |
| degradation epochs (`mission.py`) | ~2 weeks | TID, alpha drift, array fade, attrition hazards, checkpoint overhead (Daly optimal-interval model), SPE Poisson events |
| uncertainty (`montecarlo.py`) | mission ensemble | lognormal/uniform multipliers on dose, SEU, AFR, TID hardness, coating & array degradation + random solar phase; Spearman sensitivity |

Design sizing (`design.py`) closes the loop from setpoints to launch mass:
radiator area from the Tj stack-up (Tj − Rθ·P − ΔT_loop → T_rad → net W/m²),
battery from worst eclipse (energy *and* C-rate constraints), array sized EOL
with eclipse-recharge factor, then a full mass budget so every setpoint sweep
propagates into PFLOP-yr **per tonne** — the real figure of merit.

## Studies produced

- **A** baseline 5-yr timeline (clock, Tj, attrition, TID/leakage, power, checkpoint tax)
- **B** single-orbit transients: DD-SSO vs eclipse orbit vs battery-lean (idle & cold-soak)
- **C** radiator-area sweep → mass-efficiency knee
- **D** Tj setpoint sweep at two radiator specific masses (T⁴ vs Arrhenius trade)
- **E** shielding sweep (TID mortality vs launch mass)
- **F** orbit/energy-storage architecture bars
- **G** 200-run Monte Carlo + sensitivity ranking
- **H** loss waterfall (throttle / attrition / checkpoint tax)

## Model boundaries & calibration needs (be honest about these)

Every default is order-of-magnitude, calibrated to public sources; the
*structure* is the point. [MODEL.md](MODEL.md) §1–§11 states, per subsystem,
what is reduced-order and what real data (SPENVIS/GEANT4 dose transport, TVAC,
beam tests, fleet AFR telemetry, ORDEM/MASTER flux) would make the numbers
mission-grade. Not modeled at this tier: ADCS/pointing dynamics, drag &
station-keeping propellant, comms/downlink capacity, plasma charging, launch
loads, distributed multi-satellite networking.
